## 先對齊概念，再選實作

- 使用者使用「全部、關聯、範圍、進度、目前」時，先辨識真正的集合與時間語義。畫面看得到的子集、已載入的全集、持久資料及任務輸入可能不同；不要用最容易拿到的資料取代真正要求的範圍。
- 用一個具體操作例子檢查理解：改了哪個條件、會重新取哪些資料、哪些資料只是背景、何時算完成。澄清後同步修正資料流與文字，不能只換標籤。
- 有相依性的選項按決策順序排列。上層方法決定下層參數是否適用時，停用不適用參數並說明原因；不要保留一個看似可調、實際被忽略的控制。
- 對同一概念提供一個主要控制入口；需要第二個入口時說清作用層級，避免兩組相近條件互相覆蓋。

## 資料優先與維護測試範圍（2026-11-07，使用者明確回饋）

Wiki 修改先核對現有資料與相容格式，必要時在備份後救援／重建，再以準備好的資料驗收 BDD。允許刪除是必要時的選項，不是預設清庫；不能把欄位缺漏、模型額度或舊資料語義誤判為腐損。正式維護測試使用 GOOGL 最近一個月，明記實際 UTC 日期、新聞數、可重用／待處理數，分類補足也遵守同範圍。隔離回歸可使用其他股票 fixture 驗證跨股隔離，但不得啟動其他股票正式模型工作。契約與實際證據見 [WIKI_RUNTIME](WIKI_RUNTIME.md)／[TESTING](TESTING.md)。

## 把狀態當成明確的契約

先列出「誰擁有這個狀態、在哪裡保存、何時失效、哪些動作可改」。至少區分使用者草稿、已套用設定、執行中的工作版本、已保存結果與純顯示狀態。

- 不同工作區切換應保留各自的資料、選取、鏡頭及尚未套用的設定。隱藏不是重建；讀取後端設定不應無條件蓋掉較新的本地意圖。
- 保存承諾必須說清生命週期：當頁、同一設定檔的新視窗、全新瀏覽器設定檔、換裝置、服務重啟並不等價。跨視窗同步要實際開第二個視窗／分頁；跨設定檔恢復則另開乾淨設定檔驗證。不要拿其中一種結果代替另一種承諾。
- 非同步回應須核對目前資料、選取、版本與任務識別；舊回覆不能復活已取消的工作、污染新的選取或把失敗顯示成成功。
- 執行中修改設定時，先驗證新設定，再明確結束舊工作並從已完成邊界接續。閒置套用不應偷偷啟動有成本的處理；查看與討論也不等於同意重算。

## 目前看起來正常，不代表所有入口都正常

使用者明確要求：不能以「現在這個 app 畫面沒有問題」否定重連、多開網址或不同操作順序才出現的問題。修正時必須追到狀態的共同來源與所有寫入入口，並把驗證依據留下來。

- 對跨元件偏好建立一個權威狀態來源，明定哪些工作區應共享、哪些任務狀態應獨立。讓每個入口走同一套更新通知；不要只在某顆按鈕的事件裡修畫面。
- 保留可重新呈現的原始狀態與參數，依「呈現當下」的偏好產生介面。非同步回應不能拿發出請求時的舊語系／舊選取覆蓋新意圖；已完成或停止的狀態也不能被晚到的確認倒退。
- 元件若自行管理顯示，就要完整負責初次掛載、狀態更新與偏好切換。不能一部分靠全局掃描、一部分靠局部程式，又假設隱藏頁面會被自動修正。
- 翻譯介面模板和保留來源內容是兩個責任。先處理模板，再放入資料；不能為了清掉畫面中的外語而改寫使用者輸入、模型原文、引用或領域識別。
- 按改動挑選「入口 × 狀態 × 時序」矩陣：首次掛載、隱藏後顯示、切換來回、週期刷新、在途回應、失敗／重連、重新載入、另一個實際視窗。涉及持久化時再區分同來源共用儲存與獨立設定檔。不是每次把全部組合窮舉，而是不能漏掉已知會寫入同一狀態的路徑。
- 等待真正的非同步完成或下一次刷新後再斷言。測試要能控制回應先後，證明晚回覆不會把剛修好的介面改回去；只在點擊後立即截圖不足以驗收。
- 除了驗證新結果，也核對相鄰的不變條件：語言／版面調整不應改任務設定、資料範圍、選取、鏡頭或原始內容，更不能意外啟動有成本的工作。
- 測試紀錄寫清「真實瀏覽器與路由、隔離回應、正式服務、未覆蓋環境」的界線。單一視窗成功不能推論多視窗成功；模擬重連成功也不等於所有網路中斷都已驗證。

## 尊重手勢所表達的意圖

- 點擊、按住、拖曳、拖出後返回原位、滾輪、懸停、雙擊及鍵盤修飾鍵要分開判斷。不能只比較放開與按下的位置來推斷有沒有拖曳。
- 使用者在轉動或移動視角時，通常希望保留已選內容。不要在拖曳結束、滑過別處或回覆刷新時自行解除選取、重置鏡頭或重新排版。
- 聚焦時優先保留周邊脈絡，以明暗和層級表達關係；資料篩選與視覺聚焦要分開。不為了方便實作增加使用者必須先按的返回／置中按鈕。
- 控制項手勢不能被父層拖曳吞掉；拖曳也不能誤成點擊。針對 pointer capture、移出範圍、取消、失焦與按鍵未放開建立收尾邏輯。

## 版面可操作，比固定尺寸更重要

- 使用實際可用尺寸排版；工具列高度、語言、內容、字型及縮放都可能改變。不要以固定偏移掩蓋重疊。
- 隱藏或初次載入時尺寸可能為零。先提供有界幾何，再在顯示與 resize 後更新；不能把零寬度帶入除法、半徑或比例而產生滿版色塊。
- 浮動／分割工具應容許調整大小，縮小時保留可用標題及內容捲動。最近操作的工具優先，碰撞避讓不能撤銷使用者剛做的展開。
- 改版面只改版面，不應改資料、運算範圍、選取或鏡頭。必須連動的圖表則核對同一座標／日期定義，不以「看起來接近」代替一致。
- 動畫與圖示要符合產品的視覺語言、尺寸及真實工作狀態。偏好克制、清楚的專業呈現；載入中、閒置、失敗與停止不可播放相同的假忙碌效果。

## 計算與進度要可解釋

- 先定義單位、輸入集合、基準、時間窗口、去重規則與缺資料處理，再展示百分比或圖表。顯示上限不等於資料上限；背景脈絡不應重複計入目標完成數。
- 一個邏輯工作被切成多個請求時，只有該工作所需部分都成功，才算完成。取消、失敗及重試要保留已確認成果並防止重複計數。
- 缺失、尚未成熟、未知與零值要分開。排名分數、相關性、可信度、因果及觀察結果不能互相冒充。
- 視覺較稀疏不代表資料錯誤；先查證據與篩選，不為了讓畫面更密、進度更漂亮而補造關係或結果。

## 驗證整段使用路徑

修正前先把使用者的具體操作轉成可重現的失敗。修正後既驗證該症狀，也檢查最接近的相依狀態，而不是所有功能無差別重跑。

| 修改類型 | 應觀察的結果 |
| --- | --- |
| 手勢或邊界 | 真實瀏覽器按下→移動→放開；反向、移出、取消、失焦；不要只呼叫事件處理函式 |
| 隱藏／展開或尺寸 | 初次載入、零尺寸、展開、縮窄、移位、停靠、重開；文字與按鈕仍可操作 |
| 狀態保存 | 切頁前後、刷新、第二個實際視窗／分頁、全新設定檔、服務重啟；依保存契約分開驗證 |
| 跨元件顯示偏好 | 首次掛載、隱藏頁面、週期刷新、晚回應、重連；各元件與權威狀態一致，資料及原文不變 |
| 非同步工作 | 執行中改設定、取消後晚回覆、快速切換、失敗保留、完成數與去重 |
| 計算與圖表 | 已知輸入的數值、缺資料、邊界日期、圖表實際幾何與不同畫面的同一基準 |
| 外部資料更新 | 服務持續開著，實際寫入隔離資料後觀察清單／版本刷新；原選取不被搶走 |
| 新資源或部署 | 透過實際 HTTP 路由載入；核對服務中的資產與程式版本，而非只讀本地檔案 |

測試本身也可能錯。滑鼠按鍵、瀏覽器焦點、事件順序、等待條件及點擊位置都要符合真實操作；點到暗色物件不能當成點到空白。把測試修正的原因記錄清楚，不為了變綠而放寬產品行為。

## 可驗證的交付與持續學習

- 已授權、可逆且必要的工作應持續做到完整可驗收，不反覆要求使用者批准同一步驟。若真的需要補充資訊，先完成不依賴答案的部分。
- 正式資料不作測試寫入區；使用隔離資料、假回覆及獨立瀏覽器。模型／服務用量和真實寫入必須符合已授權範圍，不能為驗收自行消耗。
- 更新服務前保留恢復依據；更新後核對健康、資產、資料與原本工作狀態。原本停止就保持停止；需要接續時沿用已確認範圍，不能重新從頭處理。
- 回報清楚區分「原始碼完成、測試通過、已部署、正式頁面驗證」；交付實際結果及重要限制，不用計畫代替完成，也不用測試通過暗示所有環境都已驗證。
- 每次有概念糾正、連動漏測或重複事故，提煉成：觸發情境 → 應保留的不變條件 → 真正原因 → 能防止重犯的檢查。專案事故放專案紀錄，通用且有依據的偏好才更新本文件。
- 保持目前契約與歷史決策分層。新要求取代舊行為時，更新入口與現行規格，標明舊規格已被取代；不要讓下次初始化讀到兩個相反答案。
- 流程按改動風險選用。不要因為曾漏測某種狀態，就對所有小修改新增沒有判別力的測試、批准步驟或長篇清單。
